**核心理念**：旧项目的价值是已验证的能力机制。产出物是**新项目规格基线**：自包含（读者以执行新项目开发的 agent 为主，不接触旧仓库即可开发）、只陈述应然、不复刻缺陷。旧项目的源码、git 历史、测试、配置、既有文档一律是提炼与核验的素材，**产出物中不得引用旧项目数据**（commit、路径、文件名）。

> 术语：
> - **能力机制**：规格的基本单位，即对外可感知的能力及其支撑机制，按"动机 → 方案 → 不变量 → 失败模式"展开。
> - **缺陷**：旧项目暴露的问题。发掘来源：git 历史（fix/revert/hotfix 类提交）、TODO/FIXME/HACK 注释、死代码与重复实现、测试与代码矛盾、用户注意事项。
> - **正向约束**：缺陷转化成的"新项目须……"陈述，缺陷进入产出的唯一形态。
> - **大纲门**：撰写前的唯一一次人工确认。
> - **[待确认]**：行为或数值材料不足时的行内标注，非阻塞，汇总入附录清单。
> - **疑点清单**：无法核验项与材料间冲突（文档-代码矛盾、测试-代码矛盾）的集中出口，随附录交付；[待确认] 汇总与疑点清单并列构成附录清单集。
> - **点名机制**：用户触发时点名的能力——可为旧项目已有（重点展开）或旧项目不存在的新增能力（按同等单位规格化，立新 ADR）。

## 判别与写作原则

1. **应然终态**：只陈述新项目应当是什么；凡叙述系统自身方案随时间变化的表述，交付物正文命中数为 0——演化叙事（最初/一开始/后来/曾经/尝试过）、修复与过渡叙述（为了修复/已修复/临时方案/workaround/遗留/已知问题）、阶段性叙述（现阶段/验证期间/后续再优化/重构/重整）、实现快照（"当前逻辑是"类）、指向已移除/更名机制的描述。边界：引用外部版本号、兼容外部历史系统的描述属正当内容。已修复的缺陷不提缺陷本身，直接把修复后的机制写成正式设计。
2. **自包含**：产出不依赖旧仓库——不出现旧项目的 commit 号、路径、文件名、内部模块名；术语、类型/接口/消息名首次出现就地定义，全套文档一名一词；深度依赖外部框架编程模型（事件循环、组件生命周期等）时含"技术底座简介"（3-6 句 + 一图），无明显依赖则省略。产出物**零元话语**：不出现方法论词汇与生成痕迹（如"终态""提炼""规格基线"）、模板占位、来源过程叙述；标题直陈对象（如"X 设计规格"），卷首元信息只保留生成日期与文档间交叉引用。
3. **缺陷只走正向**：核验为"仍存在/未处理"的缺陷 → 转为正向约束集中收录；核验为"已修复" → 融入机制终态，不再提及；无法核验 → 疑点清单，禁止臆造。
4. **不虚构**：行为与数值（超时、批量大小、默认值、容量限制）须有材料依据，否则标 [待确认]；机制动机与 trade-off 无材料依据标 (推断)。
5. **以代码为准**：既有文档、测试与代码冲突时以代码实际行为为准，冲突记入疑点清单。
6. **简化三分**：已构成实际工作机制的简化 → 正式设计写入；过程残留、调试痕迹、死代码 → 不写；明确未实现的能力 → "非目标与边界"集中陈述，正文不反复出现。

## 工作流

目标项目为当前工作区或用户指定路径；用户注意事项与点名关注的能力在盘点时一并纳入。

1. **盘点**：通读目录结构、入口与主数据流、对外接口、配置项 → **机制清单**（用户点名的置顶；点名的新增能力以同等单位纳入，动机取自用户陈述的场景与约束）；全量扫描缺陷发掘来源 → **缺陷清单**，逐条核验：已修复（现机制已含）/ 仍存在 / 无法核验。
2. **大纲门**：输出 机制清单 + 缺陷核验映射 + 拟定正向约束 + 信息缺口与疑点，等用户确认后撰写；此时可附 commit/代码位置证据列供核验（仅限大纲，不进正文）。正向不明的缺陷与新增机制的设计点一律**选项式裁决**：列出候选方案、推荐项与理由，用户裁定后固化为规格或 ADR。用户声明"跳过确认"则免门直出，未裁决项标 [待确认]。
3. **撰写**：按模板成文 design.md；术语以代码主命名（入口模块及最多调用方所用名称）固化；已修复缺陷直接写终态机制，未处理缺陷仅以正向约束出现在第 8 章。
4. **自检**：任取数个机制，仅凭文档可回答"怎么实现、怎么失败"；全文无旧项目引用、无臆造数值、术语一致；演化叙事与生成痕迹（元话语、自造词、中英混杂）命中数为 0。修正后交付。
5. **交付**：输出至项目根目录 `project-distill/`（用户指定位置则从之）：`design.md` 为必产主体；术语表、疑点与 [待确认] 清单、ADR 作为 design 附录，体量大时拆出独立文件（glossary.md / adr.md / checklists.md）。

## design.md 模板

1. 概述：定位、能力范围
2. 总体架构：模块图与职责
3. 核心数据模型
4. 技术底座简介【按需】
5. 能力机制设计：逐机制"动机 → 方案 → 不变量 → 失败模式"，附 ADR 交叉引用【如有】
6. 关键流程：1-4 条端到端时序（Mermaid，命名与术语一致，图下 2-3 句说明）
7. 对外接口与配置【按需】
8. 缺陷规避约束：正向陈述清单
9. 非目标与边界
10. 附录：术语表、疑点与 [待确认] 清单、ADR【按需】

> 取舍主线：覆盖"是什么—怎么组成—怎么运转—怎么失败—怎么规避旧项目已知缺陷"。
