**核心理念**：单一事实来源。资产只陈述**应然**（意图/契约/用法/不变量），过程记录归 Git/Issue/CHANGELOG。

> 术语：
> - **持久资产**：需随代码持续维护的文档与注释，包括活文档和代码注释。
> - **活文档**：持久资产中的文档部分，如 README、ADR、CHANGELOG、设计文档等，不含代码注释。
> - **ADR**：架构决策记录。
> - **过程残留**：陈述特定时间状态的内容，如“已修复”“当前逻辑是”“已完成 TODO”。
> - **生成痕迹**：如“作为 AI”、模板占位、无意义套话。
> - **语言失配**：同一概念多名称、中英混杂、指代不明、目标读者理解困难。
> - **维护人**：资产 owner 或用户指定角色；未指定时默认当前维护者/提交者，存疑项由其裁决。

## 判别原则

冲突优先级：**失实 > 自包含 > 简注缺失 > 时效冗余 > 可读**。优先级表示处理顺序与严重度；同一位置可标记多个异味，按最高优先级处理。

逐条核对目标内容，违背即标记为异味：

1. **失实**：与实际代码或现状不符 → 最高优先级对照事实修正。
2. **自包含**：仅引用外部文档章节（如 `spec §`）未内联上下文，导致读者无法理解 → **必须保留引用并补充内联必要上下文，禁止复制完整章节，禁止直接删除导致基础信息丢失。** 若引用章节已丢失，且该信息单元仅剩引用，则整条删除；若还有独立有效信息，则删引用、留其余。
3. **简注缺失**：字段、属性、关键方法及代码块缺失注释，导致意图/契约无法确定 → 按关键信息缺失处理，优先补充。若名称自解释且无歧义，可降为一般可读问题。注释应直击意图与契约，保持简明扼要。
4. **时效冗余**：陈述特定时间状态（过程叙述“已修复”、实现快照“当前逻辑是”、已完成 TODO），或事实已由 Git/Issue 承载的副本 → 改写为持久契约或删除，不保留无效占位。上下文不可恢复时禁止臆造，整条删除。描述指向已移除/更名的机制（该机制除本句外在全仓均不可寻）→ 改写为不依赖该机制的正向契约（陈述现状应然，不写“原为 X/已更名”），或删除。
5. **可读**：包含生成痕迹、自造词、中英混杂、指代不明、不查证无法读懂的实现细节或注释冗长繁杂 → 翻译通用词、首现定义、迁移至设计文档并删除原处、精简或删除。

## 可选项

可选项默认全禁用，用户明确启用时执行。

- 注释标准：[comment-standard.md](references/comment-standard.md)。

## 执行边界

默认所有持久资产均纳入扫描；以下体裁性内容不按“过程记录”清理，但仍需处理失实、自包含、简注缺失、可读等问题：

- CHANGELOG 的过程记录。
- ADR 的决策背景、选项、后果。

支持用户在触发任务时指定豁免范围（如特定文件/目录）或调整判别标准（放宽/收紧），用户指示优先。

## 工作流

默认进入**清理模式**。

- **清理模式（默认）**：扫描标记 → 甄别过滤 → 清理计划 → 处置清理 → 验证。
- **审计模式**：用户指定“仅审计/只标记/先别改”时启用；扫描标记 → 甄别过滤 → 输出标记报告，结束，不修改资产。

1. **扫描标记**：遍历持久资产，识别违背判别原则的内容。**只标记不修改**，输出结构化列表：文件、行号、±3上下文、异味分类。异味分类固定为：失实、自包含、简注缺失、时效冗余、可读。
2. **甄别过滤**：依据执行边界排除用户指定项，记录可复用的误报规则，供技能维护时合并。存疑项标记后交维护人；维护人未决前默认不清理。
   - 审计模式：输出标记报告后结束。
   - 清理模式：继续执行第 3 步。
3. **清理计划**：列出拟清理项、理由、影响与回滚点。存疑项阻塞，不得直接清理。计划列出后直接执行。
4. **处置清理**：按原则执行清理。文档文件与代码文件分开提交；同一代码文件内的注释清理可随代码提交，但提交信息需单独说明注释清理。
5. **验证**：对照标记清单检查无信息丢失、无臆造、无死链；必要时构建/测试；保留回滚点。
