## 核心理念
单一事实来源。持久资产（需随代码持续维护的文档与注释）只写应然：意图、契约、用法、不变量；过程记录归 Git/Issue/CHANGELOG。

## 边界
CHANGELOG 的过程记录、ADR 的背景/选项/后果不按“过程残留”清理；但仍需处理失实、自包含、注释缺失、可读问题。用户可指定豁免范围或调整标准。

## 判别顺序
先重后轻，同一位置可多标记，按最高优先级处理。
1. **失实**：与代码/现状不符 → 对照事实修正。
2. **自包含**：仅引用外部章节致读者无法理解 → 保留引用，补必要内联上下文；不复制整章；引用已丢失，且该信息单元仅剩引用，则整条删除；若还有独立有效信息，则删引用、留其余。
3. **简注缺失**：字段、属性、关键方法、代码块缺意图/契约 → 补充；名称自解释可降级。注释直击意图与契约，简明。
4. **时效冗余**：过程叙述、实现快照、已完成 TODO、Git 已承载的副本 → 改写为持久契约或删除；不可恢复不臆造，整条删。描述指向已移除/更名机制（除本句外全仓不可寻）→ 改正向契约或删。
5. **可读**：生成痕迹、自造词、中英混杂、指代不明、冗长实现细节 → 翻译、首现定义、迁设计文档、精简或删除。

存疑项交维护人（owner/用户；未指定则当前维护者/提交者）裁决；未决前不清理。

## 可选项

可选项默认全禁用，用户明确启用时执行。

- 注释标准：[comment-standard.md](references/comment-standard.md)。

## 模式
- 清理模式（默认）：扫描标记 → 甄别过滤 → 清理计划 → 执行 → 验证。
- 审计模式：用户说“仅审计/只标记/先别改”时，只输出标记报告，不改资产。

标记报告含：文件、行号、必要上下文、异味分类（失实/自包含/简注缺失/时效冗余/可读）。
清理计划含：拟清理项、理由、影响、回滚点；列出后执行。
验证：无信息丢失、无臆造、无死链；必要时构建/测试；保留回滚点。
若可提交：文档与代码分开；代码内注释可随代码提交，但提交信息单独说明注释清理。
